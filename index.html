[ 07 / 08 ]  —  HOW I OPERATE

The Way
I Write Code.

001.
SHIP IT. AN IMPERFECT PRODUCT DEPLOYED BEATS A PERFECT ONE IN YOUR HEAD EVERY SINGLE TIME.
002.
OWN THE WHOLE STACK. IF IT BREAKS IN PRODUCTION, IT'S YOUR PROBLEM — FRONT END, BACK END, THE DATABASE UNDERNEATH.
003.
WRITE CODE FOR THE NEXT PERSON WHO READS IT. THEY MIGHT BE YOU IN SIX MONTHS.
004.
UNDERSTAND THE PROBLEM BEFORE YOU WRITE THE FIRST LINE. HOURS OF CODING DO NOT SAVE MINUTES OF THINKING.
005.
SECURITY IS NOT AN AFTERTHOUGHT. THINK LIKE AN ATTACKER BEFORE AN ATTACKER THINKS ABOUT YOU.
006.
NEVER STOP LEARNING. EVERY NEW STACK IS A NEW WAY TO THINK ABOUT EVERY PROBLEM YOU ALREADY KNOW.
007.
BUILD THINGS THAT MATTER. IF THE ONLY PERSON WHO'LL EVER USE IT IS YOU — MAKE SURE IT SOLVES A REAL PROBLEM.
008.
STAY UNCOMFORTABLE. IF EVERY PROJECT FEELS EASY, YOU'VE STOPPED GROWING.
009.
BE CURIOUS ABOUT EVERYTHING. THE BEST ENGINEERS ARE INVESTIGATORS, DESIGNERS, AND STORYTELLERS — NOT JUST CODERS.
